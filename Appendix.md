# Appendix: AI Prompts and Key Responses

-   **Tool:** ChatGPT

-   **Date:** September 15, 2026
-   **Purpose:** Documentation structure, Markdown drafting, wording,
    formatting suggestions, and critique.

## Step 1 --- README Structure

### Seed Prompt

> Explain what sections a good GitHub README for an R data analysis
> project should include.

### Refinement Prompt

> Revise the sections list so it's concise and uses Markdown headers and
> bullet formatting.

### Critique / Validation Prompt

> Check the Markdown syntax for correctness and readability.

### Key Response Summary

The AI suggested a concise structure including Overview, Purpose,
Requirements, Installation, Example Workflow, Validation, License, and
AI Assistance Disclosure.

## Step 2 --- README Draft

### Seed Prompt

> Here's a summary of my R project: This educational project uses a
> synthetic sales dataset to demonstrate a simple R data-analysis
> workflow. Generate a professional README.md file using Markdown.

### Refinement Prompt

> Add sections for Installation, Example Code, and License. Keep tone
> concise and professional.

### Critique / Validation Prompt

> Review the Markdown for syntax errors and suggest 2 improvements for
> clarity.

### Key Response Summary

The draft was reorganized into clearly labeled sections and included
fenced code formatting, a repository structure, validation steps, and an
AI disclosure section.

## Step 3 --- R Markdown Documentation

### Seed Prompt

> Here's my R script description: it uses a synthetic sales dataset and
> follows an import, inspection, preparation, summary, and review
> workflow. Suggest Markdown formatting and code block examples.

### Refinement Prompt

> Add syntax highlighting and improve section organization using
> sections such as Purpose, Inputs, Script Workflow, Outputs,
> Validation, and Conclusion.

### Critique / Validation Prompt

> Is the Markdown consistent with R Markdown best practices?

### Key Response Summary

The AI suggested a YAML header, clear section hierarchy, and fenced R
code chunks. The code chunks were intentionally left as placeholders so
the final R code and calculations can be manually verified.
